Subject:
HTTPS request through a load balancer

View A: health check state change

APP-3 fails at 2 s and operates again at 17 s. Three failures in sequence set the state to DOWN. Two successes in sequence set the state to UP. The time axis is to scale.

View B: server selection

The server selector compares the servers in the state UP. APP-1 has 2 active connections, so APP-1 gets the request. Then each server has 3 active connections.

View C: TLS termination

The load balancer decrypts the request and reads the path. It adds two headers and sends the plain request to APP-1. Only the load balancer holds the private key.

Sequence

  1. 1The browser asks the DNS resolver for the address of shop.example.com.
  2. 2The DNS resolver reads the A record of the name.
  3. 3The DNS resolver returns the address 198.51.100.10. The browser keeps the address for 60 s.
  4. 4The browser opens a TCP connection to port 443. Then the browser starts the TLS 1.3 handshake.
  5. 5The TLS listener reads the certificate. It signs the handshake with the private key.
  6. 6The TLS listener decrypts the request GET /cart. It gives the plain request to the HTTP router.
  7. 7The HTTP router asks the server selector for one server.
  8. 8The server selector reads the server table. It selects APP-1, which has the fewest active connections.
  9. 9The HTTP router gives the request and the server name to the upstream proxy.
  10. 10The upstream proxy takes an idle connection to APP-1 from the connection pool.
  11. 11The upstream proxy adds two headers. It sends the request to APP-1 on port 8080.
  12. 12APP-1 sends one query to the database on port 5432.
  13. 13The database returns the rows of the cart.
  14. 14APP-1 returns the status 200 and the page to the upstream proxy.
  15. 15The TLS listener encrypts the response. It sends the response to the browser on the same connection.
  16. 16The health checker sends GET /healthz to each server every 5 s.
  17. 17The health checker writes the state of each server to the server table.

Notes:

  • The load balancer sends a request only to a server in the state UP.
  • The load balancer returns the status 503 when all servers are in the state DOWN.
  • The load balancer returns the status 504 when a server gives no response in 30 s.
  • The connection to a server has no encryption. Keep the servers on a private network.
  • A server sees the address of the load balancer as the source. The header X-Forwarded-For gives the address of the browser.
  • The servers keep no session data in memory. Thus each server can answer each request.
  • This object has one load balancer. If it fails, no request gets to a server.
  • The pools use 30 of the 100 database connections.

Detail: time of the first request

The first request takes 153 ms. The time axis of the ladder is to scale. The next request on the same connection needs no DNS query and no handshake.
