Subject:
How Git stores a commit
Legend:

View A: object id of blob 94954ab

Git calculates the SHA-1 of the header and the content. The first two hex digits of the id give the directory name.

View B: entries of tree 41037b6

An entry holds a mode, a name and a raw id. The mode 40000 identifies an entry that points to a tree. The three entries make 103 bytes.

View C: the second commit uses objects again

The second commit wrote three new objects. It uses three objects from the first commit again. The parent id connects the two commits.

Sequence

  1. 1The command git add hello.txt reads the file from the working tree.
  2. 2The command writes the content as blob 94954ab into the object store. The object store then holds 7 objects.
  3. 3The command records the id of the blob in the index entry of hello.txt.
  4. 4The command git commit reads the index and writes tree 41037b6. Tree ef6ad67 exists, thus Git does not write it again.
  5. 5The command writes commit c36fe91. The commit holds the id of root tree 41037b6.
  6. 6The commit also holds the id of its parent, commit 93e4369.
  7. 7Git writes the id of the new commit into the file refs/heads/main. The branch main now points to commit c36fe91.
  8. 8HEAD holds the name of the branch main. HEAD does not change.

Notes:

  • The study object is a repository with three files, one directory and two commits.
  • An object does not change. Different content gives a different id.
  • A blob holds no file name. Two files with the same content use one blob.
  • The size of an object does not include the header.
  • A tree keeps its entries in the order of their names.
  • A tree stores the mode of a directory as 40000. The command git cat-file -p shows it as 040000.
  • A tree entry holds an id as 20 raw bytes. A commit holds an id as 40 hex digits.
  • The command git add writes the blob. The command git commit does not write it again.
  • Git does not delete blob ce01362. The first commit points to it through tree e473445.
  • The parent line adds 48 bytes to the second commit. The first commit has no parent line.
  • The main drawing shows the index pointer of hello.txt only. Each index entry holds a blob id.
  • Git can also put many objects into one pack file. This repository has loose objects only.
  • The index also holds the size and the times of each file. Git uses them to find a changed file quickly.
  • HEAD can also hold a commit id. Then a new commit moves no branch.
  • This repository uses SHA-1. Git can also use SHA-256 in a new repository.
